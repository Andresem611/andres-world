# Phase 03.3.1: Tiled Visual Map Design Pass - Context

**Gathered:** 2026-03-10
**Status:** Ready for planning

<domain>
## Phase Boundary

Do a visual design pass on the overworld map using the Tiled GUI — making buildings look like real structures, adding ground/water visual variety, and transitioning map ownership from generate-map.ts to Tiled. This phase ends with generate-map.ts retired and a .tmx source file checked into the repo. Collision, geometry, and building footprints are NOT changed — those are locked from Phase 3.3.

</domain>

<decisions>
## Implementation Decisions

### Delivery method
- Work done in Tiled GUI: open overworld.json, do the visual pass, save as .tmx + export overworld.json
- `.tmx` file committed to `public/assets/maps/` as the source of truth going forward
- `overworld.json` remains the Phaser-consumed build artifact (Tiled exports it)

### Map ownership after this phase
- `generate-map.ts` is fully retired — add prominent warning comment: "RETIRED — overworld.json is now owned by Tiled. Running this will overwrite all Tiled visual work."
- Tiled owns the overworld permanently after 03.3.1 — no regeneration, no reconciliation
- `overworld-map.test.ts` is deleted — programmatic tile tests don't apply to Tiled-authored maps; visual verification replaces them

### Tileset registry
- All available tilesets in `/public/assets/tilesets/` added to the Tiled map's tileset registry upfront — enables full navigation and palette access during design
- Tilesets to register: 1_Terrains, 2_City_Terrains, 3_City_Props, 4_Generic_Buildings, 7_Villas, 8_Worksite, 17_Garden, 19_Graveyard, 21_Beach, Interiors_16x16, Modern_Exteriors_Complete, Room_Builder_16x16
- Only the tilesets actually used will have tiles placed; the rest are just available in the palette

### Tileset selection per building type
- Claude's discretion: pick the best available LimeZu tileset for each building type
- General guidance: City Terrains/City Props for Main Street commercial buildings; Villas for Andres's House; Modern Exteriors Complete is available as a catch-all if it has better options
- No new purchases required — use only what's in `/public/assets/tilesets/`

### Visual scope — buildings
- **Key buildings get unique facade treatment:** Thoven HQ, Andres's House, Starbucks/Ventanita, Engineering Lab
  - Thoven HQ: must read as dominant/largest from Main Street
  - Andres's House: residential feel, different vibe from commercial buildings
  - Starbucks/Ventanita: two different Main Street vibes — Starbucks polished, Ventanita a tiny kiosk
  - Engineering Lab: hacker/industrial look, feels discovered (not on main street)
- **All other buildings:** shared facade pattern (roof + wall + base that works generically)
- No more single-tile BUILDING_GID (7689) blocks — every building has multi-tile treatment after this phase

### Visual scope — ground and water
- Ground texture variety is in scope (grass variants, path edges/transitions)
- Water visual treatment is in scope (water border improvements, beach/sand transitions)
- Scope level: meaningful improvement, not Phase 9 final polish — make it look good, not perfect

### Done criteria — all three required
1. **Human walk-through approval**: walk around the map in browser, judge it looks right
2. **Screenshot checklist**: Main Street, Thoven HQ, Andres's House, Beach strip, Water border — each reviewed
3. **No flat BUILDING_GID blocks**: every building has multi-tile facade treatment

### Claude's Discretion
- Which specific tileset tiles to use per building type (subject to visual confirm)
- Exact tile compositions for each building facade (roof/wall/base/door/window arrangement)
- Ground transition tile choices (path edges, grass-to-path)
- Water border / sand-to-water transition approach

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `public/assets/tilesets/` — all LimeZu packs already on disk, no downloads needed
- `public/assets/maps/overworld.json` — the Tiled import target; already has correct geometry from 3.3
- `public/tileset-preview.html` — existing tool for inspecting tileset GIDs by hovering; useful for identifying exact tiles before placing in Tiled

### Established Patterns
- **GID chain is locked**: Terrains (1–2368), Beach (2369–6368), Buildings (6369–12768), Garden (12769–19040), Worksite (19041–19680). Adding new tilesets in Tiled will extend this chain — plan the order carefully to avoid disrupting Phaser's `firstgid` expectations.
- **Three-layer architecture**: Ground layer (terrain base), Above layer (buildings, trees), Collision layer (`ge_collide:true` tiles). This layer structure must be preserved in the Tiled file.
- **TILE-CATALOG.md is the source of truth** — any new GID (from newly used tileset tiles) should be documented there.

### Integration Points
- `src/game/scenes/Boot.ts` — loads tileset images and the overworld JSON. If new tilesets are added, Boot.ts needs the new image preload calls.
- `src/game/scenes/GameScene.ts` — tilemap setup. Layer names must match what's in overworld.json — do not rename existing layers in Tiled.
- Phase 4+ interiors reference entrance tile coordinates from the geometry locked in 3.3 — visual changes do not affect these coordinates.

</code_context>
