<task type="auto">
  <name>Task 2: Write scripts/inspect-tileset.cjs — PNG tile color catalog</name>
  <files>scripts/inspect-tileset.cjs</files>
  <action>
    Create scripts/inspect-tileset.cjs (CommonJS, no external deps — uses Node.js built-in zlib and fs):

    The script reads the PNG IHDR chunk from each tileset file to confirm dimensions, then samples the center pixel of every tile cell and outputs a JSON catalog to public/assets/maps/tileset-catalog.json.

    **Script structure:**
    ```javascript
    #!/usr/bin/env node
    // scripts/inspect-tileset.cjs
    // Usage: node scripts/inspect-tileset.cjs
    // Output: public/assets/maps/tileset-catalog.json
    // No external dependencies — uses Node.js built-in zlib and fs only.
    ```

    **PNG reading approach** (no external deps):
    - Read IHDR chunk: bytes 16-23 of PNG = width (4 bytes big-endian) + height (4 bytes big-endian)
    - For full pixel data: decompress IDAT chunk using zlib.inflateSync, parse scanlines (each scanline has 1 filter byte + width*3 RGB bytes for color type 2)
    - Sample center pixel of each 16x16 tile cell: pixelX = col*16 + 8, pixelY = row*16 + 8

    **Tilesets to inspect (in order):**
    ```javascript
    const TILESETS = [
      { name: "terrains",  file: "1_Terrains_and_Fences_16x16.png", firstgid: 1 },
      { name: "beach",     file: "21_Beach_16x16.png",              firstgid: 2369 },
      { name: "buildings", file: "4_Generic_Buildings_16x16.png",   firstgid: 6369 },
      { name: "garden",    file: "17_Garden_16x16.png",             firstgid: 12769 },
      { name: "worksite",  file: "8_Worksite_16x16.png",            firstgid: 19041 },
    ];
    const TILE_SIZE = 16;
    const TILESET_DIR = path.join(__dirname, "../public/assets/tilesets");
    const OUTPUT_PATH = path.join(__dirname, "../public/assets/maps/tileset-catalog.json");
    ```

    **Output format** (tileset-catalog.json):
    ```json
    {
      "generatedAt": "ISO timestamp",
      "tilesets": [
        {
          "name": "terrains",
          "file": "1_Terrains_and_Fences_16x16.png",
          "firstgid": 1,
          "width": 512,
          "height": 1184,
          "cols": 32,
          "rows": 74,
          "tilecount": 2368,
          "sample_rows": [
            {
              "row": 0,
              "tiles": [
                { "col": 0, "localId": 0, "gid": 1, "rgb": [r, g, b] },
                { "col": 1, "localId": 1, "gid": 2, "rgb": [r, g, b] }
              ]
            }
          ]
        }
      ]
    }
    ```

    To keep the output manageable, only output the first 10 rows of each tileset in sample_rows (rows 0-9). That gives 320 tiles per sheet = 1600 total samples — enough to identify all terrain categories visually.

    **PNG decompression approach:**
    PNG IDAT chunks may be split across multiple chunks. Concatenate all IDAT chunk data, then inflate once. Each scanline: filter_byte (1) + pixels (cols * 3 bytes for RGB). Filter type 0 = None (no transformation needed for most tilesets). If filter type != 0, still output the raw bytes but note "filtered" — tile center RGB may be approximate for non-None filter types.

    **Error handling:** If a PNG file is missing or corrupt, log the error and continue with the next tileset (don't crash).

    At the end, print a human-readable summary to stdout: for each tileset, print the RGB of tile (row=0, col=0) and tile (row=1, col=0) so the agent can immediately see primary terrain colors.
